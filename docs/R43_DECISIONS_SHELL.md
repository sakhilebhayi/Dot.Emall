# R-43 shell and design system: decisions

Branch `feat/r43-shell`. Contract for feature work: `DESIGN.md` (concept, tokens, components, status vocabulary, layouts, route names) and the kit in `resources/views/components/ds/`, shown live at `/dev/kit` (local and testing only).

| # | Decision | Reason |
|---|---|---|
| S-1 | Concept: the shelf-edge price label is the unit of the interface (price, delivery, total, perforation, yellow strip), the waybill is the order. Name "Shelf Edge". Three concepts were scored from three territories (retail shelf, parcel logistics, street market); the label won. | It sits at the point of decision and answers the most repeated complaint in `R43_RESEARCH.md`: extra costs revealed late. |
| S-2 | Palette taken from the owner's logo: Stamp indigo (the chevron) for action, Awning yellow (the awning) only for the strip, scallops and count badge, never a button. Light ground is a cool paper with a breath of green, dark ground is deep indigo ink. | Honours the existing brand, avoids Amazon orange and Takealot blue, and avoids the three AI-default looks (the dark theme is not near-black plus an acid accent). Contrast is verified as numbers in `tests/Unit/DesignTokensTest.php`. |
| S-3 | Type: Schibsted Grotesk (text, headings, prices) and Martian Mono (printed codes), both self-hosted woff2 with OFL licences in `public/fonts`. The first pick, Mona Sans, was dropped because the Impeccable detector lists it as overused. | Readable, distinctive, real tabular and lining figures, a zero that reads as a zero. Not one of the banned faces, not the current app's faces. |
| S-4 | Light and dark are first class through `light-dark()` tokens and class `light` or `dark` on `<html>` (stored in `localStorage["emall-theme"]`, else the system, followed live). The Tailwind palette used by old Jetstream markup is bridged to the same tokens, and the `dark:` variants the Jetstream views carry work because the class is always set. | One switch works on every page, Jetstream included, without rewriting 25 views. New views must use tokens and `ds` components only. |
| S-5 | Four layout contexts plus auth and error frames, all anonymous Blade components with documented slots. Navigation is data (`App\Support\Navigation`) linked through `emall_route()`, which gives `#` and `data-pending-route` while a route is missing. Route names feature work must register are in `DESIGN.md`. | Feature agents can build pages before every route exists, and a pending link is visible in the DOM and in tests. |
| S-6 | Public product pages moved out of the seller back office into `x-store-layout`; cart into the store layout; buyer orders and Jetstream pages into the account layout; seller pages into the seller layout; operator pages into the operator layout. `dashboard` and `orders/show` pick their layout by role. Products index and show were rebuilt on the kit (small, and the best test of the kit); the other old pages keep their content, with colours mapped to tokens, icons to SVG and inline handlers to data attributes (`resources/css/legacy.css` bridges the old `.dot-*` classes). | Brief item 6. The legacy bridge shrinks as feature agents rebuild those pages. |
| S-7 | "Create account" and "Open a store" links are gone; every sign-in call to action goes to `login` with one sentence: accounts come from InfoDot. The login page leads with "Sign in with InfoDot" and keeps the password form below it. | Registration is closed; the audit's first P0. |
| S-8 | Seller-typed compare prices are no longer printed as "was" prices on the product page. `ds.price` prints a reference only when given the real recorded 30-day low. `StorefrontCurrencyTest` was updated for this. | Plan decision 3. |
| S-9 | `/up` is now `App\Http\Controllers\HealthController` (same contract: `DiagnosingHealth` runs first, so a dead database is a 500) with a tiny self-contained page. | The framework's health page loads the Tailwind CDN; the brief removes it everywhere. |
| S-10 | CSP: nonce-based, no third party, `style-src-attr 'unsafe-inline'` for single-element custom properties, `'unsafe-eval'` for Livewire's Alpine. No `form-action` (a form post that redirects to Paystack must not be blocked). ENFORCED by default (`SECURITY_CSP_REPORT_ONLY=false`). A real-browser run (Chrome, 52 page loads: guest, buyer, seller, operator, at 1440 and 390, with theme toggle, dialog, disclosure and search interactions) reported zero violations. A host `.env` that still says `SECURITY_CSP_REPORT_ONLY=true` stays report-only; the owner can drop that line. | Brief item 8. Feature agents must run their pages the same way (`node` script in the shell agent's scratchpad, or any Playwright run listening for `securitypolicyviolation`). |
| S-11 | Deploy: the workflow now checks the Vite manifest against the views at build time (copied from Dot.Auction), mirrors `public/fonts` and `public/images` into a docroot that is not `<app>/public` (same three cases as `build/`), and the smoke check requests both font files (200 and over 10 kB) and the logo images. `docs/deployment.md` lists `fonts` in the symlink loop. The inline manifest check was run locally against a fresh build and passes. No view that contains `@vite` ends a sentence with a `resources/css` or `resources/js` path. | A past deploy failed on exactly that check. |
| S-12 | `composer.json` gained `autoload.files` for `app/Support/helpers.php` (`emall_route`, `emall_pending`, `emall_pending_name`, `csp_nonce`). `composer dump-autoload` runs on deploy already. | Safe route helper, as in Dot.Auction. |
| S-13 | The cart count comes from `Shell::cartCount()`: a closure bound as `emall.cart_count` if one exists, else the signed-in user's `cart_items` quantity, else 0. | Guests have carts; the cart agent binds the real counter. |
| S-14 | Mail: the Laravel markdown theme is recoloured in the palette (literal hex, because email clients ignore CSS variables; the one documented exception) and the header shows the Emall mark. Team invitation copy follows the voice rules. | Brief item 5. |

## Tests

Baseline 646 tests, 7 skipped; now 703 tests, 7 skipped, 0 failing (SQLite). New: `DesignSystemTest` (kit renders, shell contract on all four contexts, titles and h1, no dead sign-up links, error pages standalone, no CDN, no literal colour in layouts and components, every ds file documented, status vocabulary, low stock only at 5 or fewer, price and label never guess, rating hidden at zero, pending routes, copy has no dashes or exclamation marks) and `Unit/DesignTokensTest` (AA for 45 token pairs in both themes, no literal colour in the stylesheets past the token file). Updated with reasons: `ResponsiveShellTest` and `Concerns/AssertsResponsiveShell` (the markup contract moved from one dark sidebar shell to four layouts and `<dialog>` menus), `SecurityHeadersTest` (nonce policy, enforced, no third party), `SingleAlpineTest` (checks the new layouts), `StorefrontCurrencyTest` (no seller-typed was price), `PublicBrowsingTest` (the header cart link shares the add form's URL, so the form is told apart by its product field), `NotificationBellTest` (rows are real buttons now), `SellerPaymentGatingTest` (status word is capitalised), `DashboardTest` (a user with no store sees "Your account").

## Checks run

- Axe 4.14 on 17 distinct pages at 1440 and 390, light and dark (107 captures): zero serious or critical violations.
- `impeccable detect` on the rendered pages (home, login, products, product, kit, 404, terms) with the built CSS inlined: 0 anti-patterns (the kit page has one advisory about `--` in printed token names, fixed). Two real findings were fixed on the way: Mona Sans (listed as overused) and Tailwind utilities generated from vendor views and compiled views (content globs trimmed, CSS 135 kB to 85 kB).
- Hallmark `sloplint` on the home page: the remaining FAILs are the built stylesheet not starting with a stamp comment (the stamp is line 1 of `tokens.css`; Vite strips comments), literal colours that the linter reads from the `.kit__theme` re-declaration in `tokens.css` (needed so the gallery can draw both themes side by side, because `light-dark()` is resolved where a custom property is declared), and Tailwind's own `.bg-white` and `dark:` utilities for the Jetstream views. Waived.
- Overflow, h1 count and title per page on every capture; tap targets at 390 (remaining small targets are inline links in the old seller pages and the product title link, whose hit area is the whole card).
- `php artisan route:cache` succeeds with the new routes (`Route::view`, controller class). The dev routes are closures by design and exist only in local and testing.

## Skills

Used, each where it adds most: `hallmark` (floor: tokens only, no tracked-capital labels, no middle-dot meta, focus, reduced motion, sloplint), `design-taste-frontend` (anti-slop house style), `awwwards` (three concepts from different territories, concept card, motion verb, the genericness test), `ui-ux-pro-max` (checklist only; its stock palette and type were rejected), `emil-design-eng` (press 0.98, ease-out only, 200ms popovers, no `transition: all`, nothing from scale 0), `design-md` (DESIGN.md format), `impeccable` (finish pass and the detector). Not used: `npx @google/design.md lint` (blocked by the brief), the Hallmark `theme.mjs` dealing and `capture.mjs` (a custom run, derived by hand, because the owner's logo fixes the palette), `react-bits`, `canvas-ui`, `scroll-world`, `gsap-*` (nothing in this system needs them). The `ui-ux-pro-max` and `emil-design-eng` skill links in `~/.claude/skills` are broken and were read from `~/Dot/.agents/skills`.

## Known limits and open items

- The old seller, operator, cart and order pages still carry their inline styles (colours mapped to tokens, so both themes work). They carry uppercase tracked labels and equal metric tiles from the first version; feature agents replace them with `ds` components.
- Footer links to help pages, categories, stores and the wishlist are `#` with `data-pending-route` until those routes exist. The shell does not write help content, because returns and delivery policy depend on features that are not built.
- Delivery on the product page label reads "Enter a delivery address to see this" until the delivery feature supplies a cost.
- The kit gallery is dev only; production never registers `/dev/kit`.
- The logo mark is cropped from the owner's PNG (`public/images/emall-mark.png`, `emall-wordmark.png`, `emall-wordmark-light.png`). A vector logo would be sharper on large screens; owner item.
- Real-device checks (iOS Safari bottom bar and `100dvh`, Android back button closing the menu dialog) were not done; Chrome emulation only.
