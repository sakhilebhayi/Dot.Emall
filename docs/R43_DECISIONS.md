# R-43 decisions taken without the owner

The owner asked for an uninterrupted build. Each decision below is the safest, most reversible choice, with how to reverse it. Add new ones at the end with the reasoning.

| # | Question (source) | Decision | Reverse by |
|---|---|---|---|
| D-1 | Refuse checkout in production while Paystack is not configured? (audit R-02) | **Yes.** `config('emall.checkout.requires_gateway')` defaults to true in production; without a usable key checkout answers "Payments are not open yet" and no unpaid order can be shipped. | env `EMALL_CHECKOUT_REQUIRES_GATEWAY=false` |
| D-2 | Seller money, commission, payouts (R-01) | **Internal ledger, no automated payouts.** Each seller group in a paid order writes a ledger entry (gross, platform commission, net, status held/released). Commission is `config('emall.commission.percent')`, **default 0** (no business term is invented); the seller sees the full fee before publishing and on every order; entries release 7 days after delivery. Paystack transfers/subaccounts and KYC are an owner item. | set the percent; build payouts later |
| D-3 | VAT and shipping (R-03) | Displayed prices are **VAT inclusive**. Stores have `vat_registered` and a claimed `vat_number` (default off); when registered, order documents show the VAT component at `config('emall.vat.rate')` (0.15). Shipping is **per-store methods** (flat, free over a threshold, collection) with optional region rules; the cart shows delivery per seller group and a total before payment. | config / seller settings |
| D-4 | Stock hold and unpaid-order cap (R-05, R-06) | Stock is held **30 minutes** (`EMALL_STOCK_HOLD_MINUTES`), extended while a payment attempt is open; at most **3 unpaid orders** per buyer or guest e-mail at once (`EMALL_MAX_UNPAID_ORDERS`). | env |
| D-5 | What "Delivered" means (R-08) | A seller must mark **Shipped** (with optional carrier and tracking number) before **Delivered**; collection orders go Ready for collection then Collected. The **buyer may confirm receipt**. Reviews unlock and the return window starts at Delivered; ledger release is 7 days after Delivered. No direct Pending to Delivered jump. | state machine |
| D-6 | Returns (R-10) | Return request **within 7 days of delivery** per order item (adopted from ECTA s44 as a standard, not a legal claim); reasons: faulty/not as described (seller pays return) or changed mind (buyer pays); seller approves or declines **with a stated reason**; unanswered for 10 days it escalates to the operator queue; an approved return, once the seller marks it received, refunds through the existing refund service. | config |
| D-7 | Account deletion (R-12) | Refused while orders, returns or refunds are open; otherwise anonymise the person and keep order and financial records. | policy |
| D-8 | Second hostname (R-?) | `TRUSTED_HOSTS` defaults to the `APP_URL` host (emall.infodot.co.za). If `emall.infodot.app` is also served, add it to the host `.env` before deploying. | env |
| D-9 | Guests | Guests browse, keep a session cart and check out with an e-mail; they follow the order by a signed magic link; orders attach to an account when someone signs in through InfoDot with the same verified e-mail. | middleware |
| D-10 | Reference prices | "Was" price = lowest recorded price in the previous 30 days from `product_price_history`, shown only when it is higher than today's price and the history is at least 30 days old; never a seller-typed original price. | feature flag |
| D-11 | Recommendations | Only from real orders and views, with minimum counts (default 3 co-purchases), labelled with the real basis and number. | config |
| D-12 | Registration | Stays closed; accounts come from InfoDot. CTAs say so. | feature |
| D-13 | Dependencies | Patch-level `composer update` of the Symfony packages flagged by `composer audit`, and `npm audit fix` without `--force`. | revert lock |

## Taken by the data agent A build (commerce schema and services), 2026-11-09

| # | Question | Decision | Reverse by |
|---|---|---|---|
| D-14 | How do variants coexist with the product price and stock every page and test already reads? | Every product has at least one variant. A product with no options has exactly one **implicit default variant** that mirrors `products.price`/`stock`/`sku`; writing either side updates the other (`VariantSync`). A product with options shows its **cheapest active variant's price** and the **total stock of its active variants** on the product row. Cart lines and order lines carry `variant_id`; one cart line per buyer **and variant**. | n/a (structural) |
| D-15 | Order state names (D-5) vs the five strings already in the database | The five existing values are unchanged. `processing` is shown as **Packing** (`OrderStatus::label()`); added `ready_for_collection`, `collected`, `refunded`. "Paid" is the payment status, not a line status. Pending may go straight to Shipped (a one-click ship; no packing step required); **Pending to Delivered is refused**. Refunded is set only by the system after a return refund. A collection parcel cannot be "shipped", a delivery parcel cannot be "ready for collection". | `OrderStatus::sellerTransitions()` |
| D-16 | A store with no shipping method at all | Still sells: delivery is **"arranged with the seller"**, R0, no date, said plainly. Set `EMALL_SHIPPING_REQUIRE_METHODS=true` to make a store without a method unbuyable. `StoreOnboarding::submit()` already demands at least one method before review. | env |
| D-17 | Money accounting for returns after delivery | A returned line **stays in the order total** (the order is what the buyer was charged); its value comes back through a refund with `kind = return`, and `RefundService::reconcile` (cancellations) ignores return refunds so the two never double count. Delivery fees are **not** refunded by a return. The refund value is the line after its promo share, fixed when the return is requested. | `RefundService` |
| D-18 | Seller ledger mechanics (D-2) | One `sale` entry per seller group when the order is paid (same transaction as the money): gross = lines after promo + the group's delivery fee; commission = percent of the **item value only**, percent snapshotted on the entry (a later change never rewrites it); per-store override table. Cancellations and returns append signed `reversal` entries (amounts of existing rows never change). The sale becomes releasable **7 days after the whole parcel is delivered** and is released by `emall:release-ledger` (hourly) unless a return on it is still open. `emall:reconcile` checks orders, payments, refunds and ledger and exits non-zero on any mismatch. No payout transfers exist. | config / `LedgerService` |
| D-19 | Guest order access (D-9) | Link token = HMAC-SHA256(app key; order id, e-mail, token version), base64url. Only its SHA-256 is stored; later e-mails recompute the same link; `rotate()` bumps the version, `revoke()` clears the hash, links expire after 180 days (`EMALL_GUEST_TOKEN_DAYS`) and die the moment the order attaches to an account. A link opens **one** order, as its buyer, and grants the session nothing else. Wrong, rotated, expired and account-owned orders all answer the same 404. Guest orders attach to an account when the **same verified** e-mail signs in (any sign-in path, via the `Login` event). Guests pay through a tokened payment-return link that verifies with Paystack. | `GuestOrderAccess` |
| D-20 | Store lifecycle vs today's "a store is live on creation" | Default unchanged (a new store is **active**). `EMALL_SELLER_REQUIRES_REVIEW=true` makes new stores start as drafts: draft, pending review, active, suspended; an operator approves, sends back **with a reason**, suspends **with a reason**, reinstates. `stores.is_active` stays the live switch every query reads (suspended/draft/pending are closed; an owner cannot reopen a suspended store). | env |
| D-21 | Seller trust ladder (plan 11) | Built from recorded data only: InfoDot sign-in (`users.infodot_signed_in_at`, written by the SSO door), InfoDot company linked, claimed registration/VAT numbers labelled **claimed**, fulfilment rate (shipped within the handling time promised), median hours from payment to shipped, return rate, review count/average, months on Emall. A number is **withheld below 5 orders** ("not enough orders yet"). The "verified" rung exists only if InfoDot's own sign-in payload sets `verified: true` on a company (`teams.infodot_verified_at`); **today's payload has no such field**, so nothing is verified and no badge shows. | config `emall.seller.trust_min_sample` |
| D-22 | Stock hold (D-4) | `EMALL_STOCK_HOLD_MINUTES` (default 30) replaces `PAYSTACK_UNPAID_WINDOW_MINUTES` (no longer read). The hold is measured from the order, **and while a payment attempt is open from the attempt, but never longer than twice the window** from the order's creation. A cancelled unpaid order no longer keeps `payment_status = pending` (it becomes `unpaid`, attempts abandoned). | env / `emall.checkout.hold_extension_cap` |
| D-23 | Notification preferences | Three categories. **Transactional** (orders, payments, delivery, returns, seller operations): always on, in the app and by e-mail; the table cannot turn it off. **Alerts** (back in stock, price drop; sibling build): in the app by default, e-mail opt-in. **Marketing**: off in every channel until someone says yes (POPIA s69). A failed notice (mail down) is logged and never undoes an order, payment or refund. Dot.Notify is an extra channel, inert unless `NOTIFY_INGEST_URL` and `NOTIFY_INGEST_SECRET` are set. | `NotificationPreferences` |
| D-24 | Tracking links | Built only from `config('emall.shipping.carriers')` (The Courier Guy, Aramex, DSV, Pargo, PUDO, Fastway via Aramex, Post Office) and only when the number matches that carrier's pattern; any other carrier is plain text. **The URL templates are the carriers' public look-ups as best known and are an owner item to re-verify before launch.** Estimates use working days (Monday to Friday, no public holidays), so every date is labelled an estimate. | config |
| D-25 | Return photos | Return requests store photo **paths** (only those under `returns/{order id}/`); **no upload endpoint was built** (the existing private upload path is for public product photos, not cheap to reuse). A feature agent adds the upload; the service already keeps and filters the paths. | n/a |
| D-26 | Dependencies (D-13) | `composer update` of the five flagged Symfony packages (and their patch-level siblings): `composer audit` is clean. `npm audit fix` without `--force`: 9 advisories down to 2 moderate (`@tailwindcss/typography` via `postcss-selector-parser`, dev tooling only); the rest needs a breaking change and is left for the owner. | revert lock files |
| D-27 | Checkout gate in the smoke script | `tests/Support/signed-in-smoke.sh` runs with `APP_ENV=production` and no Paystack key on purpose, so it now sets `EMALL_CHECKOUT_REQUIRES_GATEWAY=false` for that run only (D-1 would otherwise refuse the demo orders it builds). | the script |
