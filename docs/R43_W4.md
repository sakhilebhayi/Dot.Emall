# R-43 W4: product page, stores, reviews, Q&A, wishlist, alerts

Branch `feat/r43-w4`. Decisions D-80 to D-91 are in `R43_DECISIONS.md`. Services are in `app/Services/Storefront` (`ProductPage`, `ProductChoices`, `ProductReviews`, `DeliveryRegion`, `StoreDirectory`); the pages draw what they answer.

## For the other feature agents

- **The wishlist heart.** `<x-wish-toggle :product="$product" />` (Product or id). Props: `variantId`, `saved` (null reads the signed-in person's list once per request), `style` `icon` (a card) or `button` (labelled). Put it in the product card's `wishlist` slot: `<x-ds.product-card ...><x-slot:wishlist><x-wish-toggle :product="$p" /></x-slot:wishlist></x-ds.product-card>`. No script: a form POST to `wishlist.toggle` that returns to the page. Script (`resources/js/product.js`): saves in place.
- **Report.** `<x-report-form :action="route(...)" bag="uniqueBagName" what="this thing" />` is the "Report" disclosure used on reviews, questions, answers, listings and stores. The matching controller call is `ReviewActionController::file` or `ContentReports::report`.
- **Delivery region.** `App\Services\Storefront\DeliveryRegion::current()` is the visitor's province and postal code (chosen on a page, else the default address). `POST delivery.region` (`province`, `postal_code`, `return` = a path on this site) sets it. The shell's location chip can read and set the same thing.
- **Product links** from lists should carry `?src=search|category|recommendation|collection|homepage|wishlist` so views are attributed (`Track::SOURCES`).
- **Recommendation rail.** `pdp/partials/rail.blade.php` is a stand-in until `x-disc-rail` is merged; swap the include in `products/show.blade.php` (two places).
- **Cart count for guests.** `Shell::cartCount()` still reads 0 for a guest, so the header does not show the guest cart that `products.cart` fills. The cart agent binds `emall.cart_count`.
- **Operator queue** must render `content_reports` rows of type `product` and `store` (D-86).

## Routes (the `// --- w4 ---` block)

Public: `stores.index`, `stores.show` (`/stores/{slug}`), `products.cart`, `products.bundle`, `delivery.region`, `wishlist.shared`.
Signed in: `wishlist.index`, `wishlist.toggle`, `wishlist.sharing`, `wishlist.items.destroy|cart|alert`, `account.alerts`, `alerts.store|destroy`, `reviews.update|vote|report|reply`, `questions.store|answer|destroy|report`, `answers.report`, `products.report`, `stores.report`, `stores.message`. `products.show` stays where it was and delegates to `ProductPageController`.

## Left, on purpose

Community answers on Q&A (the service only has store answers); a messaging inbox for the store (the enquiry is a notification, the reply goes by e-mail); a per-variant gallery has no photos in the demo (covered by a test, not by a screenshot); `ReferencePrice` is computed for the chosen variant only.
